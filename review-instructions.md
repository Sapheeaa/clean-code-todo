# Инструкция для AI-ревьюера проекта clean-code-todo

что помощник должен сделать(цель):
Проведи анализ кода проекта `clean-code-todo` (файл `app.js`, `index.html` и `style.css`) и найди проблемы, которые не находит ESLint, но которые относятся к категориям задания «Clean Code»:

1. Мёртвый код.
2. Дублирование (обработчиков и логики).
3. Имена, которые не читаются без комментариев.
4. Комментарии, которые пересказывают код.
5. Функции, которые не читаются целиком.

что делать не нужно(границы):

- Переписывать приложение на фреймворк, добавлять сборщик.
- Применять DRY, KISS и YAGNI «по одному разу», чтобы показать знание терминов. Изменение должно решать конкретную проблему.
- Дробить функции только потому, что они длинные, и объединять код только потому, что он похож.
- Менять или удалять файл workflow в .github/workflows.
  Ты не редактируешь файлы. Ты только анализируешь и объясняешь.

что проверять:

- Файл `app.js` — основной объект анализа.
- `index.html` и `style.css`

критерий готовности:

- Проверены все пять категорий из задания.
- Для каждой найденной проблемы указано: место в коде (файл + строка), проблема, условие проявления, способ проверки исправления.

формат вывода:
Создай файл `review-report.md` в корне проекта. В нем выполни отчет на русском языке. Замечания должны быть сгруппированы по категориям из задания и состоять из четырех частей: место в коде, проблема, условие, при котором она проявляется, способ проверить исправление.
